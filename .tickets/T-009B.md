Owner authorizes paid Codex low effort, standard speed and freedom to choose implementation details within constraints. Avoid expanding architecture merely for future possibilities.

## Result

PC owns bounded gradual mood, weighted idle choice, finite pet/play/nap reactions, optional CPU/RAM stress. Firmware renders state and handles expiry only. Provide a bounded local HTTP reaction route following current server conventions. Brief reactions may override stress, then fresh stress resumes; stress must not permanently change mood. Validate input and coalesce/bound repeats. Optional metrics default off: independent >=80 enter / below75 clear, stale/error/missing clears contribution. Use a suitable simple local metrics source; no new provider requests or secrets.

Keep existing service the sole COM-port owner. Extend v1 JSON additively and document a compact contract before implementing it: expression validation, session/sequence identity, expiry and replay/restart behavior. State evolution depends on elapsed time in one service-owned loop, not HTTP reads/provider refresh; snapshot under synchronization for HTTP/serial consumers. Reaction delivery should be reasonably prompt through existing SerialLink (a bounded wake/push is fine); preserve pause/resume. Never let companion-only updates renew stale quota measurements. Old firmware ignores extension; old service/new firmware safely neutral. Invalid or missing companion fields must not indefinitely retain alerts; expiry also runs on total disconnect and while unrelated quota payloads continue. Reconnect sends current state, not expired reactions. Keep total line <=4095 bytes and retain fixture checks for sprint end. No large schema/framework required.
