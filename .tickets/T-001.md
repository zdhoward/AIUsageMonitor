## Goal
Add optional navigation pages and a build-time configurable screensaver to the ESP32 dashboard. Preserve the existing dashboard and telemetry behavior.

## Implementation record (2026-10-23)
- Added default-enabled Companion and Images navigation pages. Companion uses a six-second idle/happy loop with vector primitives; Images is text only.
- Added stable page IDs, optional page switches and a default-off screensaver with configurable content and timeout. Invalid enabled-saver configuration is rejected at compile time.
- Kept navigation selection separate from saver display so a wake action is consumed; held touches refresh inactivity. Telemetry/model/protocol are unchanged. Footer spacing follows the available page count.
- Updated UI/setup guidance and TEST_REPORT with verification limits. Production build passed (414,019 bytes flash / 28,648 bytes static RAM); no test suite executed.
- Device/framebuffer evidence remains pending: COM6 is visible, but no flash or capture was performed. Enabled-saver and page-disabled build variants also remain unverified. Parent owns final device verification and milestone/version decisions.

## Context
The owner requested implementation using these requirements:
- Add a simple companion page with an animated face that loops between idle and happy expressions; this is a placeholder for a future companion.
- Add an image/animation placeholder page with centered explanatory text. Image conversion, storage, and playback are out of scope.
- All available pages should be accessible through normal navigation by default.
- Screensaver is off by default. When enabled and configured, it uses a selected page already available in the firmware after inactivity.
- A tap wakes the display and returns to the page selected before the screensaver appeared; it does not advance navigation.
- Configuration is build-time. Do not add an on-screen settings page.
- Make optional features straightforward to enable/disable and select as screensaver content.
- Preserve the existing dashboard, quota data, and service protocol.

The repo currently registers Console and Details in `ui.cpp` and handles tap release in `AIUsageMonitor.ino`. It uses an ESP32 with no reported PSRAM and normally allocates a 76,800-byte RGB332 framebuffer. Keep animation lightweight and use the existing renderer architecture. Choose implementation details that fit the firmware; do not expand into arbitrary image loading or a new configuration UI.

## Steps
1. Inspect existing view navigation, touch handling, rendering cadence, and configuration conventions.
2. Add the companion and image/animation placeholder pages. Keep the companion animation small and loop between idle and happy.
3. Make available pages navigable by default and add build-time options for optional features and screensaver behavior. Select the screensaver content from an available page; disabled remains the default.
4. Track inactivity and screensaver state. When active, a tap must wake to the prior selected page without changing the selected page. Ensure navigation indicators and page cycling reflect the available pages.
5. Document the configuration and behavior in `docs/UI.md` and `docs/SETUP.md`; record actual verification and any hardware limitations in `docs/TEST_REPORT.md`.
6. Build with the repository's production firmware build script. Do not run test suites before sprint end. Provide framebuffer/device evidence for the new pages and wake/return behavior when the available hardware workflow permits; state plainly if physical evidence cannot be collected.

## Done when
- Existing Console and Details views remain functional and quota/service data is unchanged.
- All available pages are navigable by default, and optional pages can be enabled/disabled at build time.
- Companion loops between idle and happy; placeholder page has centered explanatory text.
- Screensaver is disabled by default. When enabled it shows a configured available page after inactivity; tap returns to the pre-saver page without advancing.
- Docs and implementation reflect the actual configuration and validation performed.
- `scripts/build.ps1` succeeds, no test suite was run, and changes stay within `files`.
