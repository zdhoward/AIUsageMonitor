## Goal and intention
Make the existing Companion page feel alive quickly using Grobot_Animations. The owner wants simplicity, smooth animation, and easy addition of emotions; a thin practical integration is preferred to an elaborate new engine. Owner explicitly authorized paid Codex, low effort, standard speed. Work independently within these boundaries; choose the implementation details that serve that intent.

## Required result
- Inspect https://github.com/tanmaywankar/Grobot_Animations source/examples/license. Reproducibly pin and attribute the MIT code, vendoring a small adaptation under firmware if appropriate. Use Grobot meaningfully, rather than replacing it with an unrelated renderer. No GPL reference-library code.
- Full-screen facial features only: expressive eyes, smoothly changing mouth, optional sweat. No permanent body, enclosure, labels or dashboard chrome on Companion. Preserve navigation and other pages.
- A small extensible emotion table: content, happy, curious, bored, sleepy, surprised, stressed. Independent non-blocking blink/gaze/mouth/effects with elapsed-time motion; expression changes should blend from current state. Use existing Grobot movement where useful; avoid building unnecessary physics machinery.
- Provide a small public face API for the later service integration: select expression, update/draw current state, neutral fallback. Include a bounded serial developer command for choosing an emotion so actual firmware can be demonstrated before service work. Ordinary touch stays navigation.
- Existing TFT_eSPI RGB332 canvas, rotation, screenshot and direct-panel allocation-failure fallback must remain supported. No extra full-frame buffer or per-frame allocation churn. Account for hidden page time, millis wrap and frame stalls. Personality/CPU policy belongs to the later PC task, not firmware.
- Document upstream pin, adapter changes, adding an emotion, API and resource/verification limits in docs/MINT.md.
