## Goal
Automatically dim the ESP backlight at night and brighten it during daylight using SunriseSunset.io sun times for configurable coordinates. Keep all behavioral values configurable through the existing service JSON/AIMON_* environment mechanism without reflashing.

## Context and decisions
- Owner authorized implementation of the discussed sunrise/sunset plan. Location: the owner's city; approximate city-centre coordinates 51.4779, -0.0015, timezone Europe/London. Do not infer a street address. Defaults may use this project location; document it clearly.
- PC service is the sole serial owner. Fetch on a separate background worker; never perform HTTP/file I/O in device_payload() or under its lock. Add optional validated integer `bl` (0..255) to v1 payload, including oversized-payload fallback. Older firmware ignores it. Missing/invalid bl preserves current level; explicit zero is valid. Firmware applies it for USB and Wi-Fi payloads and retains last value on disconnect, with BACKLIGHT_LEVEL at boot.
- Use stdlib HTTP with bounded timeout and bounded response; no dependencies. API https://api.sunrisesunset.io/json accepts lat/lng/date_start/date_end/timezone, time_format=unix; timestamp values may be strings. Check status=OK (INVALID_TZID is an error for explicitly configured zone), date, timezone, finite timestamps, sun_status; polar states are valid with null events. Do not compare clock strings or use one day's fixed UTC offset as a permanent timezone.
- Configurable automatic enable (default true), latitude/longitude, IANA timezone, day duty=255, night duty=40, startup fallback duty=80, sunrise/sunset centred transition duration=60 minutes, fetch refresh=24 hours, retry=15 minutes, HTTP timeout=5 seconds, firmware smoothing duration=1000ms. PWM duty is not perceived brightness percent. Validate finite/range/order/time settings; bad enabled configuration must produce a clear error rather than silently target another place. Disabled mode must need no network and omit bl (keeps legacy behavior).
- Cache a small multi-day range (yesterday through next 7 days) keyed by location/timezone in user-local app cache, with atomic disk replacement and validation on load. Continue calculating from valid cached dates through outage/restart; refresh proactively and on local date rollover/missing coverage with retry throttling using monotonic time. Keep latest computed duty when current-date cache is unavailable, or startup fallback before any valid value. Never apply yesterday's exact schedule to a new date. Bound retention and response size.
- Use zoneinfo with documented Windows tzdata requirement if needed (inspect installed dependencies); use actual date/time in configured zone, UTC epochs for arithmetic and DST-safe local dates. Sunrise-centred ramp from night to day; sunset-centred ramp from day to night, smoothstep or linear documented. Handle zero transition and overlapping long windows deterministically by clamping each ramp to daylight/night gaps. Handle polar day/night, midnight and dates spanning midnight. All views/screensavers share backlight; brightness updates must not wake idle views.
- Firmware may smooth small duty updates in loop(), nonblocking with wrap-safe millis arithmetic and bounded configurable smoothing field in payload if needed. Do not edit UI/face files or screensaver semantics.
- Expose brightness mode/current target/source date/cache or error in health/status for troubleshooting. Include source name + attribution URL whenever API-derived times are exposed; add visible Markdown backlink in brightness docs/README: Powered by [SunriseSunset.io](https://sunrisesunset.io). No raw sun times need to appear on the ESP dashboard.
- Keep --once coherent: brightness enabled should yield an appropriate fallback/cached value without hanging or starting threads; document if it does not fetch. Respect 4095-byte wire line maximum.
