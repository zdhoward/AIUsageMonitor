## Goal
Reduce local quota latency without repeatedly scanning/reaggregating full history. Keep remaining quota visible for a configurable interval BEFORE a reported reset, and record quota transitions locally so upstream jumps are explainable. No new provider requests, dependencies, credentials or watchers required.

## Implementation
1. Separate lightweight quota/activity refresh from heavy transcript discovery/aggregation. Default lightweight cadence 2 seconds, existing heavy refresh 10 seconds; unchanged active transcripts may be statted but only appended complete lines parsed. Cache directory discovery for 30 seconds, with first scan immediate and safe truncation/removal handling. Heavy metrics must retain prior values between heavy refreshes. Avoid rebuilding full usage aggregates on every serial heartbeat (cache by immutable snapshot identity and local hour/day boundaries, or equivalent simple correct approach). Do not mutate previously published Account objects during Codex merge; use fresh copies. Preserve current source priority/freshness.
2. Send an immediate coalesced serial request_push when quota measurements/reset deadlines/activity actually change; age/countdown alone do not trigger pushes. Existing 5-second heartbeat remains. Bound intervals against zero/negative values to prevent spin. Slow direct Antigravity/OpenRouter calls must not become more frequent.
3. Add bounded rotating local quota transition history under ignored logs directory. Store only instance id, source, measurement time, window kind/id, used percentage and reset deadline; no credentials, paths, names, transcripts. Only changes to percentages/deadlines/windows are recorded, not each check timestamp. Flag a drop before old reset as an unexpected transition, never infer refill solely from clock. Expose log location in docs, not public runtime personal paths. Log failures cannot stop collection.
4. Add settings reset_warning_s default 3600, nonnegative. Send a dedicated compact warning field to firmware (keep actual reset countdown unchanged). Firmware suppresses automatic saver/wakes Console/Details if any known window has available quota and reset within warning interval, including due. Unknown/100%-used excluded. Round usage carefully so known fractional availability isn't accidentally excluded near 100%. Backward compatibility: absent warning field preserves existing due-only behavior. Do not wake manually selected System/scenes or override forced !SHOW. Reuse existing display visuals; no layout changes.
5. Add focused retained regression cases for new cadence, immutable snapshot behavior, append/discovery handling, transition dedup/unexpected reset, warning payload. DO NOT RUN TESTS. Syntax compilation and production build are allowed. Update docs/log with accurate limitations. No version/tag bump until coordinator validates installed milestone.
