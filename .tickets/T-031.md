Antigravity has 5 windows in 3 pools: Flash 5h+7d, Claude/GPT (3p) 5h+7d, Argon 7d. CPAMC exposes only cooldowns for it. The existing `sources/antigravity.py` probe already gets Gemini fractions and the T3 3p buckets, so source percentages there and take attention/cooldowns from CPAMC.
Candidate: a double-wide tile (uses one spare slot) with three mini rings Flash / 3P / Argon. Settle with the owner via a mockup before T-028 renders Antigravity.

Finding (2026-10-30): a successful `gemini-3.8-flash-high` request through CPAMC on the new second Antigravity account left `quota.signals` empty. CPAMC doesn't capture Antigravity quota even on success. Options: the existing `sources/antigravity.py` probe (it needs both accounts' logins), or an owner-installed CPAMC plugin that exposes it.

## Resolved data source (2026-10-30): no plugin needed
`POST /v0/management/api-call` (management key) with body
`{"auth_index": <from auth-files>, "method": "POST", "url": "https://cloudcode-pa.googleapis.com/v1internal:retrieveUserQuotaSummary", "header": {"Authorization": "Bearer $TOKEN$", "Content-Type": "application/json", "User-Agent": "antigravity/hub/2.23.1 windows/amd64"}, "data": "{\"project\": \"<project_id>\"}"}`.
CPAMC substitutes the account token for `$TOKEN$`. The response `body` (a JSON string) holds `groups[]`:
- "Gemini Models": `gemini-5h`, `gemini-weekly` (Flash/Pro)
- "Claude and GPT models": `3p-5h`, `3p-weekly`
- "Gemini 4 Argon": `gemini-argon-wtu-weekly`
Each bucket has `remainingFraction` (missing = 0), `resetTime` (ISO) and optional `disabled` (a 5h bucket marked disabled while the weekly is exhausted; treat it as not limiting). If the daily endpoint omits the Gemini group, fall back to the `daily-cloudcode-pa` endpoint. Verified live on both accounts. Poll about every 5 minutes, not 30s.
Tile: three mini rings, Flash (5h+7d), Cl/GPT (5h+7d), Argon (7d), each pooled across accounts like the other groups.
