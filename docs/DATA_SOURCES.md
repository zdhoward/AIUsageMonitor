# Usage data sources

Baseline verified 2026-10-21 against T3 Code server 0.1.1, with the direct Antigravity probe added 2026-10-27. Local source files and databases are read without modification. The service sends no prompts and does not refresh logins or modify T3/agy state. Cache, database and transcript schemas are implementation details of their respective applications and may change.

The default transport is USB serial. Subscription quota comes from local T3 caches; the one exception is the read-only Antigravity probe described below, which reuses T3's stored Antigravity login to ask the provider for Gemini quota. The optional OpenRouter status source is different: when enabled (the code default), it reads `OPENROUTER_API_KEY` or falls back to OpenCode's local `auth.json`, and sends that key only to OpenRouter's HTTPS status endpoint. The supplied example config disables this source; enable it deliberately if wanted. Keys and OAuth tokens are never part of the device payload, logs, or `/v1/status`.

## Antigravity credential access

The direct probe is read-only with respect to T3 and agy. It discovers the configured/default Antigravity profile under `~/.t3/userdata/providers/antigravity/`, preferring the profile named by the enabled cache's `credentialFingerprint`; a sole stored profile is used otherwise. If several unrelated profiles could match, the probe reports `ambiguous account` and shows Antigrav unknown rather than mixing accounts.

The stored `acp_token.json` values are used only to request a short-lived access token from `https://oauth2.googleapis.com/token`, which is kept in memory and refreshed shortly before expiry. The access token and the token file contents never reach logs, `/v1/status`, the device payload, or error messages; failures are reduced to short fixed reasons such as `request failed (URLError)`. Request timeouts are bounded (8 s by default, `antigravity_timeout_s`); no new dependency, login flow, model call, or T3/agy write is involved. Set `antigravity_enabled: false` to skip the probe entirely.

## Unavailable or limited

- **Argon (`gemini-4-argon`):** the current Antigravity token's `fetchAvailableModels` list does not include this distinct model, and no separate independent Argon source is available. Its card therefore stays **unknown** (`--` rings and lines) and the account/status payload reports `no independent quota`. Family aggregates and the 3p shared allowance are never substituted for it; if the model appears in a future response its own quota is shown.
- **Antigravity 3p allowance:** T3's `antigravity` cache entry reports `3p-5h` / `3p-weekly`, the Claude & GPT shared allowance. That is not Gemini quota, so the collector suppresses the cache entry while the direct probe is enabled.
- **NVIDIA NIM:** there is no public usage, credit, or rate-limit API for `integrate.api.nvidia.com` keys. Only request counts seen in OpenCode history can be shown.
- **LiteLLM:** no direct proxy integration is implemented. Traffic recorded under OpenCode's `litellm` provider entries can be attributed from that history; the upstream model that answered after proxy fallbacks is not necessarily visible.
- **Claude live streaming:** transcripts record usage per completed message, not per token. "Running" status comes from T3, not from token flow.
- **Subscription spend:** Claude Pro and ChatGPT Plus report only quota percentages. The cost shown is an API-equivalent **estimate**, never a bill.
- **T3 RPC/HTTP API:** it requires a paired session token. Pairing would change T3's auth state, so it was not used. The cache files hold the same limits T3's UI shows.
- **Direct Anthropic `api/oauth/usage` probing:** T3 already does this. Repeating it would mean reading OAuth tokens in this service, so it was skipped.

## Reset deadlines and freshness

The collector runs two cadences. A lightweight pass every 2 seconds (`quota_refresh_s`) rereads the local quota caches, T3 activity and the already-parsed Codex rate limits. A heavy pass every 10 seconds (`refresh_s`) additionally walks transcript directories and reaggregates usage and OpenCode history; between heavy passes every heavy metric keeps its previous value. Transcript directory listings are reused for 30 seconds (`transcript_discovery_s`), while already-known files are still statted and only complete appended lines are parsed, so appends appear immediately and a newly created session directory is picked up within that window. The first walk is immediate; removed directories and truncated files are handled safely. Cost, token and free-provider aggregates are cached by snapshot identity plus local hour/day boundary, so they are not recomputed on every serial heartbeat. Passed deadlines continue normal polling rather than creating a busy loop, and every configured interval is clamped away from zero.

New payloads reach USB every 5 seconds by default, and a coalesced push is also requested as soon as a quota measurement, reset deadline or activity state actually changes. Age, countdown and clock-only changes never trigger a push on their own. A cache read is not a provider query: `due` may remain visible until T3 or a transcript contains a newer measurement. Percentages are retained rather than assuming a refill.

## Local quota transition history

Observed quota transitions are appended to `logs/quota_history.jsonl` (the ignored `logs/` directory; one JSON object per line). Each entry stores only the instance id, source, measurement time, window kind and id, used percentage and reset deadline: no display names, e-mails, credentials, file paths or transcript text. An entry is written only when a percentage, deadline or window set changes; repeated reads and newer check timestamps alone produce nothing. A compression of used percentage while the previous reset deadline is still in the future is marked `"x":"drop_before_reset"` as an unexpected transition. A drop after that deadline is recorded without the flag. The service never infers a refill from the clock: if nothing reports a lower value, nothing is logged. The file is bounded (`quota_history_entries`, default 400) and rotates to a single `.1` backup; write failures are logged and never stop collection.

The display's source age is based on the provider check time, not serial delivery time. An active USB connection can therefore coexist with stale provider data. Staleness defaults to 60 minutes (`limits_stale_s` 3600; firmware `CLIENT_STALE_S`); the firmware also marks a disconnected link stale after 30 seconds. A direct Antigravity reading follows the same rule: the probe polls every 5 minutes, and a failed refresh keeps the previous reading and its original check time rather than pretending it is fresh. Fast quota passes do not poll Antigravity or OpenRouter more often; both keep their own cadence.
